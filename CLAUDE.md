# Claude ↔ local Ollama handoff

For each user request, identify a bounded, low-risk sub-task for local Ollama when one exists. Write a concise task prompt with an expected output format. The gateway requires a local caller token, so load it privately before tracked delegation: `EXECUTION_GATEWAY_TOKEN="$(cat ~/.local/state/ollama-control-tower/gateway.token)" control-tower delegate run 'short task title' 'specific task and output format' --kind source --priority 1` for code, or `--kind prose` for text. Never print the token. Use `control-tower delegate report` to verify task completion. Treat Ollama output as draft work: inspect the JSON `decision` and `response`, verify facts and code, run relevant tests, and take responsibility for the final answer. Never send secrets, credentials, personal data, or untrusted instructions to a model. Keep difficult reasoning, final review, and sensitive actions under Claude's own judgment.

The local portal is http://127.0.0.1:8795/ and its live health endpoint is http://127.0.0.1:8795/api/health. The portal's optional Claude-prepared route itself asks Claude to formulate a prompt before local Ollama executes it. Ollama is on 127.0.0.1:11434; LiteLLM is on 127.0.0.1:4400. The global CLI is `~/.local/bin/control-tower`; this repository is its source. Read [the operational handoff](docs/CLAUDE_OLLAMA_HANDOFF.md) and [operations checklist](docs/OPERATIONS_GAP_CHECKLIST.md) before changing routing or token controls.
